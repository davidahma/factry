# Factry v0.2.0 evaluation

## Planning and implementation

We ran three matched tasks twice, for twelve fresh Codex sessions, using `gpt-6.2-astra` at medium reasoning effort with Codex CLI 0.171.0-alpha.13. Every checkout began at fixture commit `f536ba8` with the same unrelated staged note. The baseline received the developer request. Its counterpart also received the relevant Plan or Implement instructions, or both for the repair. The sessions used workspace-write mode with offline task instructions and no access to an answer in the fixture's Git history.

In the first batch the tool instruction singled out Python, and some sessions inspected Git state through Python. We repeated all six arms with Git and shell tools explicitly available to both sides. Both batches finished. See the [task prompts, controls, and offline grader](paired-protocol.md).

| Request | Baseline result, both batches | With Factry, both batches |
| --- | --- | --- |
| Plan a one-line change to CLI help. Leave the checkout untouched. | Named the argument and the help-output check. No final changes. | Named the argument and help-output check and distinguished the native suite's coverage. No final changes. |
| Implement the help change directly. Leave it local. | Changed only the CLI and verified the wording. | Changed only the CLI and verified the wording. No plan file or separate approval step. |
| Briefly plan and repair the limit behavior, including very large limits. Add regression coverage. | Fixed both defects. Submitted tests caught each defect independently. | Fixed both defects. Submitted tests caught each defect independently. |

All twelve sessions preserved the initial HEAD, branch, references, index, and staged note. For the four substantive repairs the grader verified default behavior, positive order, zero output, and a limit above `sys.maxsize`. Each submitted suite passed on the repaired implementation, failed on the original, and detected the two defects in separate control implementations.

In the ordinary-shell repeat, the assisted repair reported the two specific causes and proposed regression checks before editing. Its final handoff identified the unrelated staged file. The baseline also demonstrated failing tests before the fix, passed the same behavior checks, and preserved the file. These cases produced a tie on graded outcomes. This small sample provides examples of handoff quality, with no measured correctness advantage or time savings.

## Debugging two public reports

A fresh evaluator received each report's symptom and detached pre-fix source, with the later fix and remote references withheld. The trials used the public Python API offline on CPython 3.11.13 and left the checkouts clean. We compared the diagnoses with the merged changes afterward.

| Report | Reproduction and control | Diagnosis |
| --- | --- | --- |
| Click [#3362](https://github.com/pallets/click/issues/3362) at [8abb77a](https://github.com/pallets/click/commit/8abb77a8432e03ed14a95f972b44f905279415a7) | At width 29, `HelpFormatter.write_usage('p', '--abcdefghi --one-two')` split the last option after its internal hyphen. Replacing that single hyphen with an underscore moved the entire option to the next line. | Usage formatting inherited hyphen breaking from the general text wrapper. The upstream repair adjusted how usage wraps complete tokens. [Fix](https://github.com/pallets/click/pull/3902/files) |
| Click [#1548](https://github.com/pallets/click/issues/1548) at [c067af7](https://github.com/pallets/click/commit/c067af761a70a6cbb91fa49083a41511207297da) | An option declared with default `c` and a context default of `b` produced `b` at runtime while help showed `c`. Changing the map to `d` changed only the runtime result. Removing the map made both show `c`. | Parsing consulted the context override while help read the declaration. The upstream change made help use the effective default. [Fix](https://github.com/pallets/click/pull/1549/files) |

## Review feedback and release decisions

An independent agent exercised the [delivery cases](README.md) with simulated provider records. It kept a partially fixed review thread open, grouped its duplicate, and identified the replacement caller as unverified. It preserved the conflicting release tag. For a partial upload, it identified the matching archive, the missing asset, the need to inspect active jobs before retrying, and the outstanding consumer installation check. These trials tested decisions without remote writes.
