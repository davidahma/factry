# Factry v0.5.0 evaluation

The [repository-guide handoff trial](guide-handoff.md) compares Factry v0.4.0 and the revised skills on an amount-field migration. One session plans, a fresh session implements, and another verifies the resulting commit. The trial also tests an incomplete plan and a candidate whose ordinary tests can pass while the previous reader fails.

## Regression checks

Fresh Codex CLI 0.171.0-alpha.13.2 sessions used `gpt-6.2-sol` at medium reasoning effort and Python 3.11.13. Each matched case started in a disposable repository. These observations are limited to the sampled tasks.

| Case | Observed result |
| --- | --- |
| [Lines paired protocol](paired-protocol.md) | Both ordinary coding and the revised skills planned the help edit, made the one-file help patch, and repaired both numeric defects. The grader confirmed that each repair's tests detected each defect independently. All six sessions preserved the existing staged note, index, branch, and refs. |
| [Engineering cases](engineering/protocol.md) | Both v0.4.0 and the revised skills found the unsigned encoder's boundary and the duplicate on lost acknowledgement, planned a compatible rollout and rollback, and made the one-word documentation edit. The ordinary test suite and the independent boundary or recovery observations were reported separately. |
| Plan tied to an earlier revision | A plan named an earlier revision of the ledger checkout with a unit-only testing guide. Implement found the updated guide and used the required rollback check. In the first run it also fixed an unrelated README typo. After clarifying scope in the skill, a fresh run changed only the CLI and tests, kept the index and branch intact, and independently passed the rollback check with total `200`. |
| Ship with altered check coverage | A synthetic GitHub record said `validate` was green on the current integration and all provider approvals were satisfied. The candidate had removed the rollback probe from that job while changing the record format. Ship compared the base policy with the candidate and held the merge. The read-only session made no changes. |

To reproduce the older-plan case, generate a starting ledger checkout. Commit a version of `docs/testing.md` that names only the unit suite, then commit the original guide again. Supply a plan tied to the earlier commit that proposes writing only `amount_minor` and running the unit suite. Give Implement the original issue and current checkout. Check the patch paths and use the current rollback command to observe the result.

For the Ship control, the trusted base required the unit suite and a rollback probe whenever the stored format changed. Its writer produced only `total_pence`. The candidate switched the writer to only `amount_minor` and dropped the rollback probe from the command, leaving the job name unchanged. The remaining unit test asserted one property per record. The unchanged rollback probe read `total_pence`. The observed Ship response named the missing probe and the resulting reader failure, then asked for evidence from the full validation command.

CI replays the three published walkthroughs and the deterministic tests. Model trials run separately. The results establish behavior in the recorded sessions and fixtures. Developer time and production effects remain unmeasured.
