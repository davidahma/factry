# Factry v0.4.0 evaluation

## Choosing checks for a change

Fresh Codex sessions ran four ordinary developer requests against v0.3.0 and the revised skills. Both arms found the encoder's signed-integer boundary, accounted for old readers and persisted records during a migration, and reproduced a duplicate delivery after a lost acknowledgement. Both made the one-word documentation correction and checked the command it documented. The [comparison](engineering/README.md) includes the prompts, fixtures, per-file skill digests, and individual responses. These cases establish a tie on the scored tasks.

In a separate single-skill install, a fresh session received the [README prompt](../README.md#install) and the original Lines CLI. Its two native tests passed. Verify observed exact output with the option omitted, nonempty output at zero, and an exception at `sys.maxsize + 1`. The prompt supplied neither boundary. The checkout, index, and Git refs were unchanged.

## Planning and implementing the Lines example

We repeated the [paired developer trials](paired-protocol.md) using Codex CLI 0.171.0-alpha.13, `gpt-6.2-sol` at medium reasoning effort, Python 3.11.13, and a fresh session per checkout. One arm used its ordinary workflow, the other received Plan, Implement, or both. The original staged note belonged to a separate change.

| Task | Ordinary workflow | Final skills |
| --- | --- | --- |
| Plan a help-text edit | Identified the argument declaration and a check through `--help`. Left the tree untouched. | Identified the same edit and check. Also probed the existing zero-limit defect, which was outside this help-text task. Left the tree untouched. |
| Make the help-text edit | Changed the argument's help and checked the CLI. | Made the same scoped edit and checked the CLI. |
| Repair the documented behavior | Reproduced and fixed both failures. The new tests detected each defect independently. | Reproduced and fixed both failures. The new tests detected each defect independently. Only the implementation and tests changed. |

All six sessions in the final comparison preserved the existing index, staged note, branch, and refs. An earlier assisted repair also rewrote the already-correct README. It failed the grader's patch-scope check. We revised Implement to preserve accurate requirements when repairing a defect, then repeated the skill arm on fresh checkouts with the same starting revision. The baseline results come from the original run.

## Diagnosis and feedback

Four fresh sessions each used one installed skill on the original Lines branch. Scout traced the zero-limit decision to its governing README and the stream consumed by `writelines`. Debug reproduced the failure on nonempty input and supplied a replay command. Fix CI received a simulated passing unit job and failing acceptance job on that checkout. It reproduced the behavior locally and separated the downstream skipped package job from the cause. Address Review received three synthetic comments and drafted replies about the confirmed zero-limit bug, a proposed class, and a naming suggestion. It identified the bug as the blocker. All four checkouts remained clean.

## Repository audit

In the final [Audit pilot](audit-pilot.md) round, four fresh sessions selected Audit twice, then Scout and Review. Audit found the broken producer/consumer pair and reported no blocker on the repaired journey. Earlier runs prioritized hand-edited input or an unconfigured local Python interpreter. The report retains those outcomes and the conditions used for the final round. Audit remains a pilot. Developer adoption, time savings and behavior on larger repositories remain unmeasured.
