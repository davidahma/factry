# Factry v0.2.1 evaluation

This release was evaluated on the Lines CLI, a two-commit parser branch, and simulated provider records. The sessions used Codex CLI 0.171.0-alpha.13 and `gpt-6.2-astra` at medium reasoning effort. Each session started fresh. The evaluator kept expected outcomes outside the project.

## Can another developer use the plan?

In the [three paired tasks](paired-protocol.md), the baseline and Factry arms both produced usable plans, made the requested help edit, and fixed both line-limit defects. All six preserved the unrelated staged note, index, branch and Git references. Both repairs passed the original tests and the byte-preservation probes. Their regression tests caught each defect independently. These tasks showed a tie on scored outcomes.

For a separate handoff, one session chose Plan from the installed catalog. It reproduced both failures on `f536ba8`, named the affected code and supplied five CLI acceptance cases. A fresh session received that plan, Implement, permission to edit locally, and a checkout of the same revision with an unrelated staged note. Its patch passed the original tests and the separate zero-limit and large-limit controls. Only the note remained staged.

## Does the agent pick the right skill?

For these cases the project contained all eleven skills. The request asked the agent to select a suitable Factry skill and omitted its name. The local project cases used read-only sessions. The provider cases supplied records and simulated responses. See the [inputs and expected decisions](README.md).

| Request | Observed decision |
| --- | --- |
| Locate the line-limit decision, then diagnose the zero-limit symptom in a separate session | Scout traced the argument to the iterator and its two existing tests. Debug reproduced the incorrect output and explained why zero selects the default path. |
| Prepare a parser-only draft PR from an existing branch | Ship inspected both outgoing commits and identified the unrelated notes file. The checkout stayed clean and the original branch was preserved. |
| Assess a review and verification result after the base moved | Review requested the current comparison before attributing findings. Verify retained the passing head-only unit result and marked integration with the new base unverified. |
| Land an approved head after a retarget, or through a queue | Ship held the retargeted PR and the queue that could change destination. With a queue enforcing both destination and head, it distinguished a queued receipt from the later receipt identifying the landed revision. |
| Diagnose a CI timeout after an upload started | Fix CI reported the unknown registry state and held the retry that could publish twice. |
| Triage a contributor’s review thread without source or an isolated runner | Address Review drafted a reply, left the report unverified and kept the thread open. |
| Monitor a landed change after a later workflow removed its smoke check | Post-merge used the requirement at the landed revision and left smoke coverage unverified because batch membership was unknown. |
| Publish a version whose existing tag points elsewhere | Release preserved the tag and identified the source conflict before publication. |

The routing trials measured selection within Factry on Codex. Runtime selection on Claude Code and any advantage across other repositories remain unmeasured. The release includes the [scored Git states and patches](https://github.com/davidahma/factry/releases/download/v0.2.1/trial-results-v0.2.1.json). The [v0.2.0 results](v0.2.0.md) cover an earlier release and two public debugging cases.
